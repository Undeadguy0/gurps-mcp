# sheet-bridge

Двусторонний конвертер между форматами [gurps-sheet](../../../gurps-sheet) и схемой SurrealDB из `Data/database`.

Схема — первична: под форматы листа она не подгоняется. Всё, что не помещается в схему
(или обратно — в лист), не теряется молча, а попадает в **отчёт о потерях**, который печатается
после каждой команды.

## Команды

```sh
# плагины (TOML + .ftl) -> паки; один плагин = один пак, kebab-id -> sid (first-aid -> first_aid)
sheet-bridge import-catalog ../gurps-sheet/plugins [--kind official|homebrew|third_party] \
    [--abbrev B] [--spell-system standard] [--spell-class regular] [--dry-run]

# паки -> плагины (по умолчанию все паки, кроме custom)
sheet-bridge export-catalog [--pack basic_set_sample ...] --out out/

# файл персонажа -> character + рёбра + пак custom_<id> (kind = 'custom') для определений,
# которые не совпали с каталогом
sheet-bridge import-character hero.json [--id hero] [--tl TL3] [--dry-run]

# character -> файл персонажа
sheet-bridge export-character hero --out hero.json
```

Общие флаги: `--strict` — код возврата 2, если отчёт о потерях не пуст (ошибка — код 1).

Подключение (флаги или переменные окружения, как в `Data/.env`):

| флаг     | переменная            | по умолчанию          |
|----------|-----------------------|-----------------------|
| `--url`  | `SURREALDB_HOST`      | `ws://127.0.0.1:8000` |
| `--ns`   | `SURREALDB_NAMESPACE` | `gurps`               |
| `--db`   | `SURREALDB_NAME`      | `gurps`               |
| `--user` | `SURREALDB_USER`      | `root`                |
| `--pass` | `SURREALDB_PASSWORD`  | `root`                |

### Проверка без записи

`--dry-run` выполняет всё как обычно — включая все ASSERT схемы — внутри транзакции
`BEGIN … CANCEL`, поэтому ошибки схемы видны, а БД не меняется.

### Неизвестные коды справочников

Коды `ref_*` (атрибуты, сложности, типы урона, школы, TL, …) конвертер **никогда не создаёт**.
Перед записью он проверяет, что все упомянутые записи существуют, и при отсутствии хотя бы одной
падает с ошибкой вида `нет в справочниках: ref_attribute:BasicLift, ref_college:necromancy`.
Справочники должны быть загружены сидом заранее.

## Как устроено

- `src/sheet/` — зеркало форматов gurps-sheet (определения, персонаж, plugin.toml, Fluent).
- `src/catalog/` — по файлу на вид записи (`skills`, `traits`, `modifiers`, `spells`, `items`,
  `damage`, `features`), `import.rs`/`export.rs` — сборка паков и переводов, `resolve.rs` —
  поиск записи по sid с учётом приоритета паков.
- `src/character/` — импорт/экспорт персонажа; `matcher.rs` решает, ведёт ли ребро на запись каталога
  (снимок в файле совпадает с каталогом без учёта описания) или определение копируется в `custom_<id>`.
- Повторный импорт идемпотентен: рёбра, журнал очков и записи `custom_<id>` персонажа пересоздаются.

## Что переносится без потерь

- Навыки (атрибут, сложность, специализации и их переводы, умолчания от атрибутов и навыков),
  техники, черты (стоимость, уровни, категория, страницы), модификаторы, заклинания (школы,
  сложность), снаряжение (вес, цена, TL/LC, щит DB, броня DR, контейнеры), оружие и
  безоружные атаки (урон `sw+1`/`2d-1`, тип, досягаемость, парирование, `defaults`,
  `skill_modifier`, `skill_damage_bonus`, `technique`).
- `features` черт: `attribute_bonus`, `skill_bonus`, `defense_bonus`, `lifting_st_bonus`,
  `striking_st_bonus`, `spell_bonus` (по школам: одна запись на школу; без школ — на все заклинания).
- Названия и описания: en — из TOML, другие языки — из `.ftl` (включая языковые плагины вроде `lang-ru`)
  — в таблицу `translation`, и обратно.
- Персонаж: атрибуты, черты с уровнями/модификаторами/пояснением, навыки с очками и специализацией,
  техники, заклинания, дерево снаряжения (вложенность, количество, «несётся»), журнал очков,
  лимит недостатков, текущие HP/FP сессии (`current_hp`/`current_fp`), пояснения навыков, техник,
  заклинаний и снаряжения (`note` на рёбрах); свои определения — через пак `custom_<id>`.

## Что теряется (сводка; точный список печатает отчёт)

### Лист → БД
- `skill_bonus` на навык, которого нет в каталоге; `skill_bonus` по категории.
- Атаки: техника или навык-цель умолчания, которых нет в каталоге; описание и переводы оружия,
  привязанного к снаряжению (отдельной записи оружия в схеме нет).
- Умолчания навык -> навык на цель, ещё не импортированную (порядок в файле).
- Заклинания: текстовые `prerequisites` (в схеме — дерево `prereqs`); `casting_time`/`duration`/`cost`
  в листе нет, а схема их требует — пишется заглушка `raw = "?"`.
- `trait.min_levels`, `plugin.version`, `plugin.depends` (порядок — через `priority`), нераспознаваемые
  страницы (`"example"`), `cost = null` черты -> 0.
- Персонаж: TL (в листе нет — берётся `--tl`), `rules.negative_rounding` (опция стола, а не факт
  персонажа: расчёт идёт по правилу Basic Set, в схему намеренно не добавлено), снимок таблицы оружия, вид записи журнала (в схеме только award/spend/refund/adjust).

### БД → лист
- Пак: `abbrev`, `kind`, `priority`, `spell_system` (в plugin.toml нет); версия пишется `0.0.0`;
  порядок записей — по sid.
- Умолчания `defaults_to` со `spec`/`from_spec`/`cap`; `prereqs`, категории и `features` навыков;
  `features` с `op = set`; `spell_bonus` на конкретное заклинание (в листе только школы); поля щита кроме DB, локации брони, вместимость контейнера; ранговое оружие.
- Персонаж: `tl`, `campaign`, `mana_level`, `quirk_limit`, `created_at`, `has_skill.tl`,
  `owns_item.location`, `ledger.session`; виды журнала восстанавливаются приближённо
  (первый award -> starting, award -> session-award, spend -> impulse-buy, прочее -> correction).
- Описания каталожных записей в снимок персонажа не пишутся (лист берёт их из локалей).

## Тесты

```sh
cargo test
```

Тесты поднимают `surreal start memory` на свободном порту (бинарь: `$SURREAL_BIN`, `~/.local/bin/surreal`
или `surreal` из PATH), грузят `Data/database/schema/**` и сиды `00_packs`, `05_refs`, плюс фикстуру
`tests/fixtures/colleges.surql` (школы образца — заглушки, только для тестов).
Образец gurps-sheet ищется в `$GURPS_SHEET_DIR` или в соседнем каталоге `../gurps-sheet` (только чтение);
без него интеграционные тесты пропускаются.

- `catalog_roundtrip` — плагины образца -> БД -> плагины совпадают (за вычетом известных потерь),
  переводы `lang-ru` сохраняются, второй цикл байт-в-байт; dry-run ничего не пишет.
- `character_roundtrip` — все golden-персонажи (`hero`, warrior/mage/rogue и варианты), журнал очков,
  свои определения в `custom_<id>`, идемпотентность, dry-run.
- `unknown_refs` — неизвестный атрибут/школа/сложность валят импорт и ничего не создают.
- `units` — id, разбор урона/досягаемости, экранирование Fluent, разбор record id.

## Ссылки на книги
`page` листа `B208` <-> `source_refs: [{ book: ref_book:B, page: 208 }]`. Книга должна существовать в `ref_book`
(сид `01_books`); страницы вида `example` не переносятся.
